Verdict

Criterion 5 is now met. A dedicated dahiliye QA doctor (qa.dahiliye@notya.ai, specialty dahiliye) and one synthetic patient ran the whole smoke path through the real API routes (scripts/dahiliye-smoke.mts, re-runnable). Screenshots were then taken of the real UI in a headless browser, logged in as that QA doctor. The shared qa.test@notya.ai pediatri account was not changed. With the smoke evidence in place, 19 domains met all six criteria and were Strong. Update 2026-09-17 (DAH-SCORE2-VERIFY): SCORE2/KVR is now Strong too, making 20. Every SCORE2 coefficient, both baseline survivals and all four region scale pairs were checked line by line against the ehab309 Updated Supplementary Material (Suppl. methods Tables 2–3). No differences were found. The published worked example in Suppl. methods Table 4 (4 regions × 2 sexes) is reproduced in tests/score2.test.ts, and SCORE2_ONAYLI=true. A second synthetic patient (non-diabetic, 50-year-old man who smokes) runs the numeric path in the smoke script: 8.8% from approved labs, a draft category, then the hekim lock. SCORE2-OP (≥70) and SCORE2-Diabetes are not part of this row; they are tracked as separate ledger items. Two stay Partial: Lab/Belgeler (the shared extraction engine was not re-audited, and the smoke run approved seeded panels rather than an uploaded PDF), and the prompts/ lock (rubric criteria 1–2 don't apply to it).

Smoke path — evidence for criterion 5 (DAH-WOW-SMOKE)

What was captured, and how. Real screenshots of the running app (local next dev on the production Supabase project), taken with a headless Chromium logged in as the dedicated QA doctor qa.dahiliye@notya.ai. They are not mockups and were not rendered from fixtures. All data belongs to one synthetic patient, TEST — Dahiliye Smoke (sentetik) (67 y, E, invented birth date, no T.C., no phone, no e-mail). The path itself ran through the real API routes in scripts/dahiliye-smoke.mts (run 2026-09-17, 83 requests, 15 checks, 0 failures). One step was not run end to end: the two lab panels were inserted as the extractor leaves them (onayli=false), then approved with the real /api/doktor/belgeler/analiz/onayla route. The PDF upload and Claude vision extraction were skipped. Re-run: npm run dev then npx tsx scripts/dahiliye-smoke.mts.
  1. KB kaydet 152/94 → evre 1 taslak; eksik ölçüm tekniği listesi → 409 kapı; tam liste → onay.
  2. Lab onayla: önceki panel (muayene yok → route "Lab değerlendirme" muayenesi açar) + güncel panel. Onaylanmadan önce şerit boş kaldı (yalnız onaylı satır).
  3. Dahiliye adımları: dm, dmdongu, lipid, tiroid, nodul, kvr, ckd (+nefro sevk paketi), evkayit ×6, ilacizlem, anemi, obezite, tarama, asi, htpanel, hf, antikoagulan, pulm, gi, ekg (acil bulgu onaysız → 409), ekgonay, kirmizi, nudge ×3.
  4. Hekim kilidi: 22 kart alanı kilitlendi; kilitlenemez alan (dm.insulin_doz) → 400. Tarama sonucu "Nota ekle"ye kadar nota yazılmadı (C6 doğrulandı).
  5. SGK rapor (statin) KVR kilidini okudu; DB taslağında ad / T.C. boş → hekim kilidi.
  6. Check-up ileri65 paketi → 8/14 kalem onaylı labla yeşil → birleşik rapor TASLAK → hekim onayı → "hekim onaylı" + Yazdır/PDF.
  7. Portal ön anket: PIN olmadan 401 → PIN → anket → doktor "Subjektif'e ekle".
  8. Kohort paneli: KB/LDL hedef dışı + eGFR <45 bayrakları → 1-tap hatırlatma (mesajda klinik değer yok) → 7 gün içinde ikinci gönderim atlandı.

Found and fixed during the smoke run

  1. /api/doktor/belgeler/analiz/onayla: when a patient had no muayene yet, the route tried to write a specialty column that notes doesn't have, so approving that first lab returned a 500. The column is removed from the insert, and the smoke run now covers this path.
  2. Antikoagülan engine: with no approved creatinine, apiksaban showed "azaltılmış doz kriteri yok". It now says "değerlendirilemez — eksik: onaylı kreatinin" (unit test added).

Out of scope (sevk only, never faked)

ICU/sepsis bundles · chemotherapy · dialysis prescription · coronary cath protocol · CGM device stack · bariatric OR pathway (obezite card sends a referral) · FRAX (licensed) · live Medula submission (SGK drafts + e-Nabız envelope only). Next sprint: DAH-WOW-NEXT ledger.
