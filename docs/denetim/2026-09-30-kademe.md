## 3. Heavy task: SOAP body + öneri, luna vs luna-pro (Kaan's test account, read-only)

Kaan's test doctor (`c4989e29…`) has one session without a transcript and no notes, so the pair ran on a synthetic
pediatric AOM transcript (2 028 chars, `.denetim-out/_tmp-soap-kademe.mts`) against his test patient's chart
(DOB from `patients`); `soapNotuUret` in-process, nothing written. luna = kill-switch on; luna-pro = tiering on
(`soap` body derin, öneri `kademe: 'derin'`).

| | luna (`gpt-6-luna`, default effort) | luna-pro |
|---|---|---|
| wall time, body + öneri awaited | **19.1 s** | **50.4 s** (2.6×) |
| body (A) tokens | 4 550 in → 1 777 out (720 reasoning), $0.0010 | 19 464 in → 5 323 out (3 059 reasoning), $0.0038 |
| öneri (B) | hit the 2 000-token cap (`length`) → G2 `kesildi` → koruyucu disabled → 599, öneri empty | two OpenRouter 502s → G1 → koruyucu disabled → 599, öneri empty |
| `ai_confidence` | 0.98 | 0.96 |

Quality (hand read of both notes): S / O / A / vitals / ilaçlar / takip are equivalent and both correct (all vitals,
both diagnoses, four drugs with "Belirtilmedi" doses, 10-day follow-up). Differences: **luna-pro kept the red-flag
instructions** (ateş > 48 s, kulaktan akıntı, uyku hali, ense sertliği, nefes darlığı → hemen gelin) in the plan and
added a "Büyüme değerlendirmesi" line; **luna dropped the red flags entirely** — a real omission for a pediatric note.
luna-pro coded H66.91 (laterality, ICD-10-CM) vs luna H66.9. luna kept the TEDAVİ / ÖNERİ / TAKİP plan tags, luna-pro
did not. Verdict: luna-pro is the better note; 2.6× the time is invisible in the background path (`[id]/end` returns
at A time, B via `waitUntil`), cost ≈ 4× but still under a cent per note. Both öneri (B) failures are pre-existing
behaviour (NOTYA-NOT-HIZ-02 already saw B at the 2 000 cap) and would have gone to Sonnet with the koruyucu on.
