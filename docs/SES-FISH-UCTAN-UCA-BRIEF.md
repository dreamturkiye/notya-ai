## Architecture to build
When persona is aysekaya AND FISH_API_KEY is set: the client does NOT call `Conversation.startSession` (ElevenLabs SDK) at all — no ElevenLabs WebSocket, no ElevenLabs agent, no ElevenLabs billing. Instead:

1. **Capture + live ASR (Deepgram)**: getUserMedia (audio only, echoCancellation: true, noiseSuppression: true — these are OUR responsibility now, ElevenLabs used to provide this), stream 16kHz linear16 PCM (reuse the AudioWorklet pattern already in the repo — check public/ses/ for existing worklets used by sesCalar.ts, do not write a new resampler if one already exists for capture) over a Deepgram Live WebSocket, reusing `createDeepgramToken` (lib/transcription/deepgramClient.ts) for a short-lived scoped key. NEW config distinct from the dictation DEEPGRAM_OPTIONS (that one has diarize:true, utterance_end_ms:1500 tuned for a whole-visit recording): a conversational-turn config — language 'tr', model nova-2-medical or nova-3 (check Deepgram's current TR model support, use the best available), interim_results true, endpointing tuned for a natural conversational pause (start ~300-500ms, make it a named constant so it can be tuned after Dr. Gökhan's test), smart_format true, punctuate true, NO diarize (single speaker — the doctor).
2. **Turn detection**: a finished Deepgram utterance (is_final + speech_final, or your own endpointing on top of interim results — pick the more reliable signal from Deepgram's actual event shape, verify against Deepgram's current docs) is ONE turn. Do not dispatch on interim results. Do not dispatch twice for one utterance — this is the exact bug being eliminated; write a unit test that feeds a sequence of interim+final Deepgram-shaped events for one utterance and asserts exactly one dispatch.
3. **Single dispatch, no ElevenLabs webhook involved**: call a NEW route (or extend an existing one — decide, but it must NOT go through ElevenLabs' Custom-LLM webhook contract, that whole request/response shape existed to satisfy ElevenLabs, not us) that invokes `ayseCevapla` with kanal:'ses' directly, server-side, exactly once per finished turn. Add a short-lived per-turn idempotency guard keyed by (asistanSessionId, a turn nonce generated client-side per utterance) so that if the client's own network layer ever retries the same turn, the model is never invoked twice for it — store the nonce briefly (in-process Map with a TTL, or the existing devre.ts pattern's approach to short-lived per-process state) and return the cached in-flight/completed promise's result instead of re-dispatching. Cover this with a test: two rapid identical-nonce requests → one model call, two responses.
4. **Streaming response + Fish TTS**: reuse `sesLlm.ts`'s sentence-gating logic (SES_BLOK_ESIGI, the finished-sentence gate from 5e5014ee — keep the "eager" fix, it is correct in principle, the bug was the double ElevenLabs dispatch racing it, not the eagerness itself) to feed complete sentences to Fish exactly as `fishCalar.ts`/`fishIsle` already do. Reuse the existing Fish player code (fishCalarOlustur, fishYeniCumleler) as-is where it doesn't assume ElevenLabs is also running — audit for any remaining assumption that ElevenLabs' onMessage/conversation object exists (e.g. `conversationRef.current`, `fishAcikRef` gating tied to an active ElevenLabs session) and remove those assumptions for the Ayşe-only path.
5. **Barge-in / interruption**: while Fish is speaking, keep the Deepgram stream open and listening. On new speech detected (Deepgram VAD/endpointing signal, or a simple energy-based check if Deepgram doesn't expose one directly — check its docs), immediately stop Fish playback (fishRef.kes(), already exists) and cancel the in-flight model call for the turn that was speaking (AbortController — check if aiCagir/the model call chain already supports cancellation; if not, this is required, not optional — ElevenLabs used to give us this for free).
6. **Acoustic echo (critical, new risk)**: ElevenLabs previously handled not-hearing-its-own-voice internally. Now Fish's audio plays through the SAME device speaker the mic is capturing from. Mute/gate the Deepgram send while Fish audio is actively playing (client already tracks Fish playback state via fishRef/onBasladi/onDurdu callbacks in the existing hybrid code — reuse that), OR rely on getUserMedia's echoCancellation constraint if the browser's AEC is reliable enough — pick one, document the choice, and write a test/manual-check note for the acceptance section below. This directly prevents a worse version of today's kendiSelamiMi bug (there is no vendor-side self-echo filter anymore).
7. **Screen sync / continuation / silence-on-typing / page-follow / "bana anlat" / local-time greeting**: every one of today's existing behaviors (NOTYA-SES-DEVAM-01 continuation past the spoken cap, NOTYA-SES-SESSIZ-01 mute-on-typing, NOTYA-SAYFA-HASTA-01/02 page-follow, NOTYA-SES-OKU-01 read-aloud-on-request, NOTYA-SELAM-SAAT-01 local-time greeting) must keep working for Ayşe Kaya under the new pipeline. These are mostly server-side (ayseCevapla, gunOzeti) and should be unaffected by the transport change, but the client-side wiring (AsistanOturumContext state machine) changes substantially — go through each one and confirm/fix. List any that need a follow-up in the report rather than silently dropping one.
8. **Session/context correctness**: reuse the SAME asistan_sessions row / shared session id mechanism as today (written/voice share one conversation, tab-switch-between-personas correctly resets per a803f667's fix) — this part of today's work was verified correct and must not regress. Add a persona-switch test: start on aysekaya (Fish path), switch to a different persona (ElevenLabs path) in the same shared session, switch back — no bleed, no crash from tearing down a Fish-mode session's client state incorrectly.
