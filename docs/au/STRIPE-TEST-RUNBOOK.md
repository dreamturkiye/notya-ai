# Stripe test-mode runbook (owner, about 15 minutes) — AU-BETA-02

**Initial compliance draft – external legal review later.** Nothing in this repository has been run against Stripe's real test mode: the adapter is proven only against fabricated fixtures and the Stripe SDK's own request builder (`lib/ulke/fatura/saglayici.test.ts`). This runbook is how YOU close that gap. Use a Stripe **test-mode (sandbox)** account only. No real card, no live key.

1. **Key.** Stripe dashboard (test mode) → Developers → API keys → *Create restricted key*. Give it: Write on Checkout Sessions, Payment Intents and Refunds; Read on Charges. (The restricted-keys page lists no resource names, so if the screen asks for something different, follow it — and see step 8.) Copy the `rk_test_…` value.
2. **Connect.** In the Australian build, open Billing → "Your own merchant account" → Stripe → paste the key → *Save connection*. Expected: "Connection saved … checked with the provider". A `rk_live_` key must be refused; a wrong key must say "Stripe rejected that key".
3. **Webhook.** In Stripe (test mode) → Developers → Webhooks → add endpoint with the URL shown on the Billing screen (`…/au/api/ulke/odeme-webhook/stripe?d=<your account id>`), events `checkout.session.completed`, `checkout.session.async_payment_succeeded`, `charge.refunded`. Copy the signing secret `whsec_…`, paste it into the connection form (disconnect and reconnect, or save again with the key and the secret).
4. **Invoice.** Create an invoice for any patient (for example AUD 110.00). Press **Pay**: you are sent to a Stripe-hosted page on your own test account.
5. **Charge.** Pay with the Stripe test card `4242 4242 4242 4242`, any future expiry, any CVC (from Stripe's testing docs; not fetched by this job — check https://docs.stripe.com/testing). Expected: back on Billing the invoice turns **Paid** within seconds (set by the signed webhook, not by the browser). If it stays "Awaiting payment confirmation", the webhook secret or URL is wrong (Stripe dashboard → the endpoint → event deliveries shows the HTTP status: 400 bad signature, 404 no endpoint).
6. **Refund.** Press *Refund in full* (or a partial amount). Expected: the invoice shows the refunded amount; in Stripe the payment shows the refund.
7. **Reconcile.** Reconciliation → "Last 30 days" → *Run reconciliation*. Expected: the invoice row says **Matched, refunded** (or **Matched** before the refund). Create one test payment directly in the Stripe dashboard to see **Missing in Notya**; download the CSV and check its first column reads `provider`.
8. **Report back** (to the AU build owner): did step 2 pass with the permissions above (if a request failed, Stripe's request log for the key names the missing permission), did the webhook deliver 200, did the match say what is written here. Anything else is a defect to fix before a live key is ever allowed.

Not covered by this runbook: payouts / balance transactions (not read), Stripe Connect OAuth (not built; needs a Notya platform `client_id`), live mode (off; the database accepts only `test`).
