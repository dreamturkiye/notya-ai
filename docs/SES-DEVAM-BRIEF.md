## Problem
ElevenLabs drops a Custom LLM stream at ~30 s (custom_llm_error: LLM Cascade Error: TimeoutError). NOTYA-SES-ERKEN-01 (merged today) closes the voice turn at the spoken cap (SesAkisi SOZ_BEAT_SINIRI=5 sentences, "Devamı ekranınızda Hocam") or a 22 s guard, and finishes the screen answer in the background (waitUntil). NOTYA-SES-OKU-01 (PR #460) reads the last screen answer aloud, uncapped, on "bana anlat / devamını oku" (okumaIstegiMi in konusma.ts), no model call.
Dr. Gökhan's requirement: the spoken özet must NOT stop mid-flight — historically (before tek-beyin) it ran past 30 s and finished. He wants that back.

## Design (Kaan approved)
Automatic continuation. The voice turn still closes at the limit (so the call is never dropped), but as soon as the screen answer is complete the client sends a hidden continuation turn and Ayşe resumes from where she stopped, reading the remainder without a model call.

1. Server — ayseCevapla.ts (ses channel): track what was actually spoken this turn (SesAkisi.soylenen) and, when the turn was cut (cap reached → onSinir fired, or the 22 s guard fired in sesLlm), compute the remainder after the full screen answer is ready: kalan = konusmaYap(ekran, temizle, { sinirsiz: true }) minus the sentences already spoken (match by sentence prefix; if matching fails, kalan = full uncapped text). Persist on the session turn: active_context.sesDevam = { turId/anahtar, kalan, olusturma: ISO } (session JSON; no migration). Clear it whenever a new real user turn arrives. If the model finished within the turn (nothing cut) → no sesDevam.
   - The guard-timer case lives in sesLlm.ts (bekci): make sesLlm tell ayseCevapla (or write after the background promise completes) that the turn was cut so kalan gets computed. Simplest: ayseCevapla exposes the spoken list in its result; sesLlm, after the background `sonrasi` completes, writes sesDevam if kim !== 'bitti'.
   - The "Devamı ekranınızda Hocam" sentence: when a continuation WILL follow, do not speak it; speak nothing extra at the cut (the pause is the continuation gap). Keep DEVAMI_EKRANDA only for the case where continuation is impossible (no ekran, error).
2. Server — ses-ekran route: include `devam: boolean` (sesDevam exists and not yet consumed) in the polling response for the latest turn.
3. Server — sesLlm.ts: recognise the hidden continuation marker as the user message: exact text `[devam]` (also accept "devam et" / "devam" alone as a natural spoken continuation). On it: if sesDevam exists → stream `kalan` as speech (uncapped, sentence by sentence via the existing yaz), clear sesDevam, do not call the model, do not write a new ekran bubble (or write nothing). If no sesDevam → fall through to normal handling (okumaIstegiMi already covers "devamını oku").
4. Client — AsistanOturumContext.tsx: in the ses-ekran polling handler, when a turn arrives with devam === true and the agent is not currently speaking (use the SDK isSpeaking / status; if it is speaking, wait for it to finish, poll again), call conversation.sendUserMessage('[devam]') exactly once per turn key (guard against duplicates). The hidden message must NOT appear as a doctor bubble in the transcript UI (filter '[devam]' from rendered messages). If the doctor interrupts (a real user transcript arrives before the continuation is sent), do not send it.
5. Interaction with OKU-01: "bana anlat" still works (reads full last answer, uncapped). DEVAM-01 makes it unnecessary for the normal case.
6. Tests: konusma/ayseCevapla unit test for kalan computation (spoken prefix removed; fallback to full); sesLlm test in tekBeyin.test.ts: turn cut by cap → session has sesDevam → `[devam]` request streams exactly the remainder, no model call (modelIstekleri unchanged), sesDevam cleared; a real user turn clears sesDevam. Use the existing fake stream (yanit.gecikmeMs / gecikmeSonrasi) to simulate a >cap answer.
7. Docs: OPEN-COMMITMENTS.md row NOTYA-SES-DEVAM-01 DONE (kod) with the design summary; note that ERKEN-01's "Devamı ekranınızda" is now the fallback only. SITE-MAP entry for the [devam] marker.
