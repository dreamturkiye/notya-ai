# Ayşe search / chart Q&A regression after the Luna switch — root-cause note (2026-09-29)

Scope: "no such patient" / empty / evasive answers, weak search, and a falsely claimed open chart since the brain moved
from Sonnet to OpenRouter GPT-6 Luna (2026-09-27). Investigated on main 49a57c05. Hypothesis under test: "Sonnet-era
tuning did not carry over to Luna". Verdict: **mostly false** — the dominant causes are deterministic code changes made
on 2026-09-29, with one prompt defect that Luna amplifies. Branch `fix/luna-search-regression` fixes the safe part.

## Fixes on `fix/luna-search-regression`
- F1 `ayseCevapla.ts` — when no chart is attached this turn, the system queue carries `DOSYA_YOK_BLOGU` ("[BU TURDA AÇIK HASTA DOSYASI YOK] … dosya uydurma, 'dosyası açık' deme, hastanın adını iste"). Model-agnostic; removes the contradiction in cause 2.
- F2 `personaEngine.ts` rule 13 — no longer points at `hasta_bul`; asks for the name when no dossier block is present. (Voice prompt l.277-291 still mentions `hasta_bul`; it is only used by the legacy ConvAI path — left, see ledger.)
- F3 `aktifHasta.ts` — an İlk-10 dossier question (`soruTuruBul` ≠ null: aşıları/ilaçları/büyümesi/özetle…) counts as a reference to the patient opened by name in this session (still `odakKaynak='soz'` only, page focus still never binds — DOSYA-ISTE-01 kept). Partially restores cause 1.
- F4 `ayseCevapla.ts` — chart-compile failure now logs `[asistan/chat] dosya bağlamı kurulamadı`.
- Tests: `aktifHasta.test.ts` (+1), `tekBeyin.test.ts` (+1). Ran the 6 affected files: 111 pass; the 2 failures are NOTYA-SES-BAGLAM-KUCULT-01 subtests that fail identically on main (order-dependent background hafıza call, already in the ledger). `tsc --noEmit`: no errors in touched files.
