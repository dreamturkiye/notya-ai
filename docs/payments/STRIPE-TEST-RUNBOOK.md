# Stripe test-mode runbook (doctor or clinic, about 15 minutes) — BYO-PAYMENTS-01 (all Stripe countries)

**Initial compliance draft – external legal review later.** The owner reported on 2026-10-22 that the adapter was checked against Stripe's real **test mode** responses (PaymentIntent shape, the `notya_invoice_id` metadata, `latest_charge.amount_refunded`, refunds) with no code change needed; that run is not reproduced in this repository. This runbook is how a doctor repeats that check on their own account before going live (`docs/payments/STRIPE-LIVE-RUNBOOK.md`). Use a Stripe **test-mode (sandbox)** account only. No real card.

1. **Key.** Stripe dashboard (test mode) → Developers → API keys → *Create restricted key*. Give it: Checkout Sessions: Write; Payment Intents: Read; Refunds: Write; Charges: Read; everything else None. (Stripe's page lists no complete resource list, so if the screen labels differ, follow it — and see step 8.) Copy the `rk_test_…` value. A key that starts with `sk_` (secret key, any mode) is refused.
2. **Connect.** In your country's build, open Billing → "Your own merchant account" → Stripe → paste the key → *Save connection*. Expected: "Connection saved … TEST mode". A `sk_` key must be refused; a wrong key must say "Stripe rejected that key". The badge must read **TEST MODE — no real money**.
3. **Webhook.** In Stripe (test mode) → Webhooks → create an event destination (*Your account*, payload **Snapshot**) with the URL shown on the Billing screen (`…/<country path>/api/ulke/odeme-webhook/stripe?d=<your account id>`, where the country path is /us, /uk, /ca, /au or /nz), events `checkout.session.completed`, `checkout.session.async_payment_succeeded`, `charge.refunded`. Reveal and copy the signing secret `whsec_…`, paste it into the connection form (save again with the key and the secret).
4. **Invoice.** Create an invoice for any patient (for example 110.00 in your currency). Press **Pay**: you are sent to a Stripe-hosted page on your own test account.
5. **Charge.** Pay with the Stripe test card `4242 4242 4242 4242`, any future expiry, any CVC (https://docs.stripe.com/testing). Expected: back on Billing the invoice turns **Paid** within seconds (set by the signed webhook, not by the browser). If it stays "Awaiting payment confirmation", the webhook secret or URL is wrong (Stripe → the endpoint → event deliveries shows the HTTP status: 400 bad signature, 404 no endpoint).
6. **Refund.** Press *Refund in full* (or a partial amount). Expected: the invoice shows the refunded amount; in Stripe the payment shows the refund.
7. **Reconcile.** Reconciliation → "Last 30 days" → *Run reconciliation*. Expected: the invoice row says **Matched, refunded** (or **Matched** before the refund). Create one test payment directly in the Stripe dashboard to see **Missing in Notya**; download the CSV and check its first column reads `provider`.
8. **Report back** (to the build owner): did step 2 pass with the permissions above (if a request failed, Stripe's request log for the key names the missing permission), did the webhook deliver 200, did the match say what is written here.

Live mode is available since 2026-10-22: see `docs/payments/STRIPE-LIVE-RUNBOOK.md`. Not covered here: payouts / balance transactions (not read), Stripe Connect OAuth (not built).
